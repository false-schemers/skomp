# SKOMP Precursors

This directory holds the importer that brings skomp's sources in from its three
sister projects. Nothing in this repository links to a sister checkout or to a
branch of one: the files are copied in and committed here, so a clone of skomp
builds on its own.

## Running the importer

The sister checkouts are assumed to sit beside skint. With the usual layout

```
work/skint   work/marv   work/WCPL/wcpl   work/skomp
```

run the importer from the skomp repository root, with any Skint interpreter:

```
$ skint pre/import.ssc
```

An argument names the directory holding the sisters, if it is not the
repository's parent:

```
$ skint pre/import.ssc /home/gwendolyn/src
```

The importer writes `pre/SOURCES.txt`, which records for each sister the path it
copied from, the commit, the date, whether that tree had uncommitted changes,
and every file it brought with its size. It also writes `skomp_src.h`, which is
where `skomp --version` gets the three commit strings. Both files are generated;
do not edit them.

## Versions

These are the versions skomp was last imported from. A later sister will usually
work, but the four parts are meant to be replaced together: the compiler library
and the `srt` runtime agree on the object layout bit for bit, and MARV's own
target descriptions are read by the compiler's output.

| part | version |
|---|---|
| skint | 0.8.6 (`219290d`, 26 Nov 2026) |
| marv | `6c4becd`, 26 Nov 2026 |
| wcpl | `c1af82f`, 26 Nov 2026 |

MARV and WCPL carry no version string of their own, so the commit is the
version. `pre/SOURCES.txt` holds what the last import actually took.

## What is copied, and what is not

Two of the lists are **derived** rather than written out, so they cannot fall
behind the compiler:

  * the compiler's own units come from the `(include ...)` forms in
    `compile.sld`;
  * the `clib/` tree comes from `*shadow-library-names*` in `cups-front.scm`.

A shadowed library name whose `clib/` file is missing stops the import. That is
the invariant skomp's packaging rests on: skomp ships `clib/` and no other part
of the host's library tree, so every name the compiler may serve has to be in
there. Skint used to *borrow* such a name from the host's own `lib/`, which
worked and was also a trap; the borrowed libraries were copied into `clib/` and
the fallback removed.

Four things are left out on purpose:

  * **`skint/opt/n_enhtty.*`** — skomp never enters a REPL, and the includes
    that would want these are guarded by `OPT_ENHTTY`. The importer fails if
    they arrive anyway.
  * **skint's `lib/srfi` and `lib/mask.slm`** — `clib/` is complete, and the
    compiled world is not the interpreter's.
  * **marv's `lib/`** — across every program compiled so far, generated modules
    name only `$scmrt` and `$scmi` as system modules, and both come from the
    compiler's own `srt/`. If the code generator ever emits another
    `(include system ...)`, that library has to be imported too; `test/`
    checks the generated modules for exactly this.
  * **marv's `srt/`** — a copy of the compiler's own. skomp uses the
    compiler's, which is the one that matches it.

WCPL needs no library files: its headers and libraries are embedded in the
binary.

## Regenerating skint's own precursors

skomp does not regenerate anything. `skint/t.c` and `skint/s.c` are autogenerated
in skint, from `pre/t.scm` and `pre/s.scm` there; see that project's
`pre/README.md`. skomp imports the generated C.
